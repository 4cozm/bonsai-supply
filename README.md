# Bonsai Supply — 프론트 셸

EVE 코퍼 행어 재고를 보고, **부족분을 한 번의 붙여넣기로 사는 것**이 이 화면의 유일한 임무다.
그래서 화면에서 가장 대비가 높은 요소는 표가 아니라 멀티바이 매니페스트다 — 이 제품의 최종
산출물이 붙여넣을 문자열 한 덩어리이기 때문에, 버튼 뒤에 숨기지 않고 앞에 뒀다.

빌드 단계가 없는 순수 정적 파일이다. GitHub Pages에 그대로 올라간다.

## 실행

```bash
node dev-server.mjs
```

`http://localhost:4173`. 의존성 없음. `file://`로 직접 열면 상대 경로 에셋이 깨진다.

## 지금 동작하는 것

- **충족률 바** — 채움 색이 재고 수준을 따라 레드 → 앰버 → 그린으로 연속 이동하고,
  퍼센트는 트랙 **안에** 얹혀 열을 차지하지 않는다. 두 구간 모두 선형이 아니라 이징을 쓴다.
  선형으로 섞으면 20%짜리가 이미 주황으로 보여서 정작 위험한 저재고가 덜 위험해 보인다.
  100%를 넘긴 재고는 바를 100%에서 멈추고 끝에 눈금을 찍는다.
- **추이 스파크라인** — 재고 수량 로그를 품목별로 그린다. 색은 충족률 바와 같은 램프를 쓴다.
  **hover하면** 세로 가이드가 따라붙고 그 시점의 날짜·시각과 수량이 뜬다 (`8/11 01:30  234개`).
- **예상 비용** — 품목별 `부족분 × 단가`, 매니페스트 하단에 합계 ISK.
  단위는 T / B / M 까지만 쓴다. K는 실제로 잘 쓰지 않아 오히려 읽기 어렵다.
- 필터(부족 · 전체 · 충족), 품목 검색
- **목표 수량 인라인 편집** — 값을 바꾸면 부족분·색·매니페스트·합계가 즉시 재계산된다.
  별도 설정 페이지 대신 이 자리를 설정 지점으로 잡았다.
- 매니페스트 포함/제외 토글, `품목명<TAB>수량` 복사

레이아웃은 1240px 아래에서 한 열로 접히고(매니페스트가 위로 올라온다), 640px 아래에서는
표가 카드로 쌓인다. 좁은 화면에서 아이콘과 추이는 접지만 **부족분과 충족률 바는 끝까지 남긴다** —
부족분이 잘려 보이는 것이 이 화면에서 가장 나쁜 실패다.

## 백엔드에 필요한 것

### 재고 수량 로그 (스파크라인의 입력)

10분 간격 크론이 행어 재고를 찍어야 스파크라인이 실제 소비량을 보여준다. 두 가지를 먼저 정해야 한다.

**적재량.** 매 틱마다 전 품목을 쓰면 품목 200개 기준 하루 28,800행, 1년 1,050만 행이다.
대부분의 품목은 10분 사이에 움직이지 않으므로, **직전 값과 다를 때만 기록하고 읽을 때 앞의 값을
이어 쓰는(carry-forward)** 방식이면 적재량이 크게 줄어든다.

**보존.** 10분 해상도를 영구 보관할 이유가 없다. 최근 며칠만 10분으로 두고 그 이후는 시간 단위로
말아 넘기는 정책이 필요하다. 기간은 아직 정하지 않았다.

프론트가 기대하는 형태는 `history: number[]`(오래된 것 → 최신) 하나뿐이다. 저장 방식이 무엇이든
API가 이 배열로 내려주면 된다.

### 그 밖에

**데이터.** [app.js](assets/js/app.js)의 `loadItems()` 하나가 `window.BONSAI_MOCK`을 읽는
유일한 지점이다. API가 생기면 이 함수만 `fetch("/api/stock")`으로 바꾼다.

**typeId와 부피.** 목업의 `typeId`는 전부 `0`, `unitVolume`은 임의값이다. 실제 값은 ESI에서
온다 — `corporations/{id}/assets`(보유 수량·type_id), `universe/types/{id}`(이름·volume).
`name`은 인게임 표기와 **정확히** 일치해야 한다. 멀티바이가 이름으로 품목을 찾기 때문에,
철자가 어긋나면 그 줄은 조용히 매칭에 실패한다.

**인증.** Discord OAuth2, 테넌트 해석, 행어 선택 모두 아직 없다. 상단 행어 셀렉트는 표시만
한다. `tenantKey`는 반드시 서버가 세션에서 결정해야 하며 클라이언트가 고르게 두면 안 된다.

**필터.** 지금은 부족/전체/충족 셋뿐이다. 더 세분화하기로 했고, 기준은 아직 정하지 않았다.

## 시세

[pricing.js](assets/js/pricing.js)에 어댑터 경계만 만들어 두고 목업을 물려 놨다. 정적 사이트에서
브라우저가 서드파티 시세 API를 직접 호출하려면 두 가지가 성립해야 하는데, **둘 다 아직 확인되지
않았다.**

1. **CORS** — 응답이 우리 origin을 허용해야 한다. 아니면 브라우저가 막고, 백엔드 프록시가 강제된다.
2. **레이트리밋** — 호출이 사용자 브라우저마다 따로 나간다. 서버 한 곳에서 나가는 게 아니다.

후보는 typeId 단위 집계를 주는 Fuzzwork(키 불필요)와 매니페스트를 통째로 감정하는 Janice(API 키
필요 — 키가 필요하다는 건 정적 프론트에 둘 수 없다는 뜻이다). 붙이기 전에 CORS 동작을 직접
확인해야 한다.
